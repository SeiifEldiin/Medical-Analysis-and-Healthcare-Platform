# Medical Analysis and Healthcare Platform

A Flask-based web application that predicts the likelihood of several diseases from patient data, using pre-trained machine learning models. The interface is fully Arabic (RTL) and built with Bootstrap 5.

> **Disclaimer:** This project is for educational purposes only. Predictions are generated by statistical models and **are not a medical diagnosis**. Always consult a licensed physician for actual medical decisions.

## Overview

The platform exposes a simple web form for each supported condition. The user fills in the relevant clinical values, the app scales/prepares the input the same way it was prepared during training, and a pre-trained scikit-learn model returns a prediction (and, for some conditions, a confidence score).

## Features

| Condition | Route | Algorithm | Notes |
|---|---|---|---|
| Diabetes | `/diabetes` | K-Nearest Neighbors | 8 clinical features (glucose, BMI, insulin, etc.) |
| Autism | `/predict` | Random Forest | Based on the 10-question AQ-10 screening + demographics |
| Anemia | `/animia` | SVM (SVC) | Hemoglobin, MCH, MCHC, MCV |
| Heart Disease | `/heart` | Random Forest | Returns a confidence percentage |
| Liver Disease | `/liver` | Random Forest | 10 liver function panel features |
| COVID-19 Severity | `/corona` | Logistic Regression | Demographic + comorbidity based risk |

Each prediction is rendered on a shared result page (`final_result.html`) with a simple positive/negative outcome indicator and, where available, a model confidence score.

## Tech Stack

- **Backend:** Python, Flask
- **ML / Data:** scikit-learn, pandas, numpy (models serialized with `pickle`)
- **Frontend:** HTML, Bootstrap 5 (RTL), Font Awesome, Google Fonts (Cairo)
- **Deployment:** Docker

## Getting Started

### Prerequisites

- Python 3.11+
- pip

### Local Installation

```bash
# Clone the repository
git clone https://github.com/<your-username>/Medical-Analysis-and-Healthcare-Platform.git
cd Medical-Analysis-and-Healthcare-Platform

# Create and activate a virtual environment
python -m venv venv
source venv/bin/activate    # on Windows: venv\Scripts\activate

# Install dependencies
pip install -r requirements.txt

# Run the app
python app.py
```

The app will be available at `http://127.0.0.1:5000/`.

### Run with Docker

```bash
docker build -t medical-analysis-platform .
docker run -p 5000:5000 medical-analysis-platform
```

## Known Issues / To-Do

- **Case-sensitive filename bug:** `app.py` loads `models/scaler_autism.pkl` (lowercase), but the actual file in `models/` is `Scaler_autism.pkl` (capital S). This works on Windows (case-insensitive filesystem) but **will crash on startup on Linux/Docker**, since the container build in the `Dockerfile` runs on `python:3.11-slim` (case-sensitive). Fix by matching the exact filename casing.
- The homepage copy mentions kidney disease (الكلى) as a supported analysis, but there is no corresponding route or model — either implement it or update the copy.
- `Covid_2(final_xgb).pkl` (XGBoost model, ~488 KB) is bundled in `models/` but never loaded or used in `app.py` — the app only loads the logistic regression COVID model. Remove it or wire it in if it's meant to be used.
- `requirements.txt` has no pinned `xgboost` dependency, which is consistent with it being unused — but should be added if the XGBoost model is ever wired in.
- No `.gitignore` is present; `venv/` and `__pycache__/` are excluded from the Docker build via `.dockerignore.txt` but could still be committed to git accidentally.
- `app.run(debug=True)` is fine for local development but should be disabled (or run behind `gunicorn`/`waitress`) in any real deployment.
- Model files were serialized with `scikit-learn 1.6.1`; loading them with a newer scikit-learn version raises `InconsistentVersionWarning`. Consider pinning `scikit-learn==1.6.1` in `requirements.txt` to avoid silent prediction drift.
